# Docker 与虚拟机的区别

> 分类：运维 | 日期：2026-10-12 | 标签：docker, 容器, 虚拟化

## 架构对比

| 维度 | Docker 容器 | 虚拟机 |
|------|-------------|--------|
| 隔离级别 | 进程级（共享宿主内核） | 硬件级（每个 VM 一个完整 OS） |
| 体积 | MB 级 | GB 级 |
| 启动速度 | 秒级 | 分钟级 |
| 性能损耗 | 接近原生 | 有 Hypervisor 虚拟化开销 |
| 隔离强度 | 较弱（内核共享） | 强 |
| 代表 | Docker、containerd | VMware、KVM、VirtualBox |

## 关键区别

- **虚拟机**：Hypervisor 虚拟出一套硬件，每个 VM 都要安装完整的 Guest OS（内核 + 用户态）。
- **容器**：不虚拟硬件，靠 Linux **Namespace** 隔离视图（进程树、网络、文件系统、PID 等）+ **Cgroups** 限制资源（CPU、内存），所有容器共享宿主机内核。所以 Linux 容器跑不了 Windows 程序；Windows 上跑 Linux 容器，底层其实是套了一层轻量 VM。

## 镜像与容器

- **镜像（Image）**：只读模板，由分层文件系统（overlay2）叠加而成——Dockerfile 每条指令生成一层，多层可被不同镜像共享，这也是"镜像越多越不占空间"的原因。
- **容器（Container）**：镜像的一个运行实例，在只读层之上加一个**可写层**；删除容器即丢弃可写层，需要持久化的数据必须挂 volume。

类比：镜像是"类 / 程序"，容器是"实例 / 进程"。

## 我的理解

一句话：容器 = 被隔离和限流的特殊进程；VM = 软件模拟出来的整台电脑。要密度、启动速度、交付一致性选容器；要强隔离、跑异构操作系统选 VM。生产环境常见两者叠加：云主机（VM）里再跑 Kubernetes 容器集群。
