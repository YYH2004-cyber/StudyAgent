# 递归与分治思想

> 分类：算法 | 日期：2026-10-12 | 标签：算法, 递归

## 递归三要素

写对任何递归函数，先回答三个问题：

1. **终止条件（base case）**：什么时候停？没有它就是无限递归、栈溢出。
2. **缩小规模**：递归调用处理的子问题必须比原问题更小，并且朝着终止条件走。
3. **返回与组合**：拿到子问题的解之后，如何组装出原问题的解。

```python
def fact(n):
    if n <= 1:                 # 1. 终止条件
        return 1
    return n * fact(n - 1)     # 2. 缩小规模 + 3. 组合结果
```

## 分治 = 分解 + 解决 + 合并

分治（Divide and Conquer）把问题拆成**互不重叠的同类子问题**，分别求解后合并结果；递归只是它的实现手段。

经典案例——归并排序：

```python
def merge_sort(arr):
    if len(arr) <= 1:                # 终止条件
        return arr
    mid = len(arr) // 2              # 分解：一刀两半
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])
    return merge(left, right)        # 合并：两个有序列表归并

def merge(a, b):
    result, i, j = [], 0, 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            result.append(a[i]); i += 1
        else:
            result.append(b[j]); j += 1
    return result + a[i:] + b[j:]
```

复杂度分析：每一层合并的总工作量是 O(n)，一共 O(log n) 层，所以时间 O(n log n)；空间 O(n)（辅助数组）+ O(log n) 递归栈。归并排序稳定、时间稳定（最坏也是 O(n log n)），但要额外空间；这是它和快排的核心区别。

## 其他分治经典

- **快速排序**：分解（按 pivot 划分）→ 解决（递归两侧）→ 合并（原地完成，无需显式合并）；平均 O(n log n)，最坏 O(n²)。
- **二分查找**：每次丢弃一半，O(log n)，分治的最简形态。
- **逆序对统计**：在归并排序的 merge 过程中顺便数跨分界的逆序对。
- **大整数乘法**（Karatsuba）、**最近点对**。

## 易错点

1. 忘写 base case 或子问题没变小 → `RecursionError`（栈溢出）。
2. 存在大量重复子问题时（如朴素斐波那契 O(2ⁿ)），加记忆化 `@functools.lru_cache` 或直接改写为动态规划。
3. Python 默认递归深度约 1000（`sys.getrecursionlimit()`），深递归要改成显式栈的循环版本。
4. 递归过程中传可变对象（list/dict）要小心：对上一层的修改会污染兄弟分支。

## 我的理解

递归的心法是"相信子函数已经做对，只写好当前这一层"——本质是用数学归纳法的方式写代码。分治的套路化问法是：这个问题能不能切成同构的小问题，且合并代价可控？看到"排序、树、一半一半"这些关键词，先想分治。
