# StudyAgent · 本地个人知识库问答助手

基于 **RAG（检索增强生成）** 的个人知识库问答 Demo：把 `notes/` 下的 Markdown / PDF 笔切块、向量化存入本地 Chroma 向量库，提问时先检索最相关的笔记片段，再交给本地大模型生成带出处的回答。全程本地运行，数据不出本机。

> 📌 **关于本项目**：这是一个以学习为目的的个人项目——通过从零搭建一个完整的 RAG 应用，一路演进到自主决策的 Agent，来学习 LLM 应用开发的各个环节（文档加载、切块、向量化、检索、Prompt 工程、function calling、Agent 循环、对话界面）。项目持续更新中，完整计划见下方[后续规划](#后续规划)。

## 功能

- 📚 多学科笔记入库（Markdown + PDF），语义检索而非关键词匹配
- 🤖 本地 LLM（Ollama + qwen2.5:7b）生成回答，回答末尾标注 `[来源：文件名]`
- 💬 Streamlit 聊天界面：多轮对话历史、temperature 可调、示例问题一键提问
- 🔒 完全离线：embedding 用本地 bge-m3 模型，LLM 走本机 Ollama

## 项目结构

```
StudyAgent/
├── App.py            # Streamlit 聊天界面（入口）
├── RAG.py            # RAG 链路：检索 → 拼上下文 → 生成回答
├── api/              # Ollama 连接配置（OpenAI 兼容接口）
├── chat/             # LLM 对话封装（普通 + 流式）
├── loader/           # 文档加载（Markdown / PDF）
├── chunker/          # 文本切块
├── vector_db/        # Chroma 向量库：建索引 + 检索器
├── notes/            # 知识库语料（各学科笔记）
├── bge-m3/           # 本地 embedding 模型（体积大，不入库，需自行下载）
└── chroma_db/        # 向量库数据（运行时生成，不入库）
```

## 快速开始

### 1. 准备本地环境

- 安装 [Ollama](https://ollama.com/)，拉取对话模型：

  ```bash
  ollama pull qwen2.5:7b
  ```

- 从 [HuggingFace](https://huggingface.co/BAAI/bge-m3) 或 ModelScope 下载 bge-m3 模型文件，放到项目根目录的 `bge-m3/` 文件夹（或自行修改 `vector_db/` 中代码指向的路径）。

### 2. 安装 Python 依赖

```bash
pip install streamlit chromadb openai pypdf
```

### 3. 建立向量索引（首次运行）

```bash
python vector_db/index.py
```

### 4. 启动问答界面

```bash
streamlit run App.py
```

也可以不走界面，直接命令行测试 RAG 链路：

```bash
python RAG.py
```

## 后续规划

> 演进主线：从**固定流程的 RAG 流水线**进化为**能自主决策的 Agent**——由模型自己决定要不要检索、检索什么、何时给出答案，而不是代码写死的"检索 → 生成"两步；同时把它从"自用脚本"打磨成"顺手的个人学习工具"。

### ✅ 已完成

- [x] **模型调用层**：封装 Ollama 的 OpenAI 兼容接口，普通对话 + 流式输出（`api/`、`chat/`）
- [x] **知识库入库**：Markdown / PDF 加载 → 滑窗切块 → bge-m3 向量化 → Chroma 持久化（`loader/`、`chunker/`、`vector_db/`）
- [x] **RAG 链路**：语义检索 → 拼装带来源的参考资料 → 生成带出处的回答（`RAG.py`）
- [x] **问答界面**：Streamlit 聊天界面，多轮对话记忆、temperature 可调、示例问题（`App.py`）

### 🚧 近期 · 把流水线补扎实

- [ ] **流式输出**：接入已写好的流式接口，回答逐字打出，替代整段等待
- [ ] **引用透明化**：折叠面板展示命中的笔记片段与相似度分数，检索过程可查
- [ ] **相似度阈值**：低分命中不进上下文，全不过线就直说"没找到"
- [ ] **查询改写**：多轮追问"它呢？"时先改写成独立问题再检索，解决指代导致的检索落空

### 🤖 主线 · Agent 化改造

- [ ] **检索工具化**：把检索注册为 function calling 工具，由模型决定是否调用、传什么查询词
- [ ] **Agent 循环**：Reason → Act → Observe 循环手写实现（不依赖框架），设最大步数防失控
- [ ] **更多工具**：列出笔记清单、按文件名取整篇笔记等——工具多于一个，"决策"才有真实意义
- [ ] **过程可视化**：界面上实时展示 Agent 每一步动作（正在检索什么、拿到了什么）
- [ ] **上下文管理**：对话历史超长时截断或摘要压缩，避免撑爆上下文窗口

### 🔍 检索质量进阶

- [ ] **混合检索**：BM25 关键词 + 向量语义两路召回互补（精确术语、缩写靠关键词，语义靠向量）
- [ ] **重排序（rerank）**：先粗召回 top 20，再精排出 top 5 的两段式架构
- [ ] **元数据过滤**：按学科目录限定检索范围（Chroma where 过滤）

### 🧰 产品功能完善

- [ ] **文档上传 + 增量索引**：界面拖拽上传即入库，只索引新增/改动的文件
- [ ] **知识库管理页**：浏览已收录文档与切块情况，支持删除
- [ ] **多会话管理**：侧边栏多个对话可切换、重命名，历史持久化不丢
- [ ] **参数面板增强**：模型一键切换、system prompt 可编辑（出题模式 / 费曼老师模式）
- [ ] **导出对话**：一键存成 Markdown，好答案回流进知识库沉淀

### 🎓 学习特色功能

- [ ] **学习卡片**：从笔记自动生成问答卡片，翻牌自测
- [ ] **出题模式**：随机挑一篇笔记出题、批改讲解——给自己造一个私人模考系统
- [ ] **每日复习**：结合间隔重复算法，每天推送到期卡片，从被动问答走向主动学习

### 🏗️ 工程化

- [ ] **日志与统计**：记录每次提问、命中片段与耗时
- [ ] **RAG 评测集**：小规模问答对量化检索命中率与回答质量，优化有据可依

## 说明

- 向量库使用 GPU 做 embedding 编码（`vector_db/retriever.py` 中 `device="cuda"`），没有 GPU 的机器请改为 `"cpu"`，但入库和检索会明显变慢。
- 换用自己的语料：把文档放进 `notes/`，重新执行第 3 步建索引即可。
